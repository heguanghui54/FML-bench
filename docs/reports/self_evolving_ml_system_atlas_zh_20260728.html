01 · System Architecture

五层控制面：从事实源到论文门禁

系统不把“模型写出的方案”直接等同于研究进展。每层都保存来源、冻结哈希和可见性边界。

LAYER 1

FML Ground Truth

上游基准与任务事实。

  • 7 个 agent 实现
  • 18 个 task 配置
  • 基线与主指标
  • validation / protected test
LAYER 2

Knowledge & Contracts

把源码审计转为可检索契约。

  • source-hashed cards
  • 指标语义与方向
  • 预算 / 声明边界
  • published prior 隔离层
LAYER 3

Adaptive Control

节点局部选择，不展开笛卡尔积。

  • 策略候选池
  • 可见证据快照
  • operator contract
  • 回溯与修复
LAYER 4

Evidence & Statistics

结果、过程与不确定性分开治理。

  • 摘要哈希与路径
  • 完整 trial block
  • paired comparisons
  • Holm correction
LAYER 5

Paper Gate

论文写作依赖冻结证据包。

  • claim registry
  • 完整性硬门槛
  • 多角色盲审
  • human release decision
受保护测试只允许在候选冻结后执行一次，其结果不能回流搜索控制器；若暴露后继续改代码，就必须使用新的隐藏评估或标记为 post-hoc。

03 · Search Operators

同一预算下比较 7 种研究搜索范式

“自我演进”不是新增第八个万能代理，而是让控制器依据任务条件和可见证据选择、编译并审核已有搜索策略。

节点内部自适应循环

每个可执行节点都有自己的小循环，不需要重启整条研究流水线。

SEE
读取冻结快照只看该节点允许的 validation / process evidence
SELECT
选择策略与 operator按任务、失败模式、预算和先验组装局部动作
ACT
编辑与执行只修改声明的 target files，记录执行后端与日志
REVIEW
类型化审核区分代码失败、实验失败、统计不足和完整性违规
ROUTE
推进 / 重试 / 换策略 / 回溯失败轨迹保留，成功也必须通过硬门槛

08 · How To Use

现在怎样理解和运行这套系统

本页是项目地图，不替代 CLI、协议、日志或结果文件。所有结论都必须回到证据源。

阅读顺序

  1. 先看“证据进度”，确认当前能说什么。
  2. 再看 8-stage 流程，理解一次研究如何被规划和门禁。
  3. 用代理与任务卡理解搜索空间。
  4. 实验完成后重新生成 report 与 paper package，升级为完整版。
不要这样读：303 个图谱节点不代表 303 条验证成功的经验；182 条计划记录不代表 182 次实验已完成；pilot 的单次分数不代表最终排序。

最小可审计流程

python3 -m ml_scientist.cli bootstrap \ --out artifacts/ml_scientist/bootstrap \ --results benchmark_results
python3 -m ml_scientist.cli campaign \ --matrix artifacts/ml_scientist/codex_ssh_protocol/run_matrix.csv \ --logs artifacts/ml_scientist/codex_ssh_protocol/campaign \ --phase pilot
python3 -m ml_scientist.cli report \ --results benchmark_results/controlled \ --metric-reports metric_reports/controlled \ --out artifacts/ml_scientist/experiment-report
